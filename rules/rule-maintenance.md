# 主动记录与规则维护

> 触发：发现有复用价值的事实或经验、用户纠正、规则不适用、重复失败、设备变化或新旧约定冲突。

## 持续授权

用户于 2026-09-12 明确授权：后续工作中主动记录值得保留的信息、修改需要调整的规则、沉淀有效经验，并评估和更新与旧规则冲突的内容，无需逐次询问。发现后在当前任务的合适阶段实际落盘，不只提出“建议记录”。优先完成当前工作；会导致当前错误的规则及时修正，其余在收尾时整理。

这项授权适用于本项目的规则、上下文、参考资料及模型记录。研究、审查或诊断对目标模型和应用仍默认只读，但可以做上述知识维护；当前用户明确要求“不改文件”或“仅提建议”时，本轮不落盘。维护规则本身不扩大打印、删除用户资产、对外发布、安装或全局配置的操作授权。

## 记录什么，放在哪里

| 内容 | 位置与要求 |
|---|---|
| 每次适用的简短约束和长期授权 | AGENTS.md；保持入口简短 |
| 用户偏好、设备基线、最近工具观测 | 项目上下文；区分稳定事实与临时状态，标明来源或核验日期 |
| 可复用的设计、操作和验收方法 | 对应领域规则；明确触发条件、动作和验证依据 |
| 已知故障和临时措施 | 对应排障资料；保留症状、适用版本、有效措施、未证实原因和复核 / 退出条件 |
| 单个模型的尺寸、配置、试打结果与修改 | `models/<模型名称>/print-notes.md` 或已有模型记录；沿用本地保存范围 |
| 有复用价值的来源和取舍 | [资料入口](references.md)；直接链接、适用范围及检查深度 |

只记录会改变后续判断、减少重复调查或避免已发生错误的内容。优先更新已有条目，不复制对话、完整日志、敏感值或无效尝试流水账；没有新结论时无需改文件或制造记录。

## 经验与冲突的处理

- 区分用户要求、官方说明、现场观测、实测结果和假设。单次成功可记录为限定条件下的经验；未验证推测保留为待验证项，不能升级为全项目硬性要求。
- 模型尺寸和一次试打结果留在模型记录；跨模型复现且材料、方向和配置明确的结论才提升为设备基线。设备、材料或预设改变时复核适用条件。
- 新要求明确替代旧要求、事实已过时、条款重复或限制过宽时，主动替换、合并或删除，并检查引用处；不要只在末尾追加相反规则。
- 表面冲突先检查任务、版本、材料、时间和授权范围。可按现有证据判断时自行更新；存在不同适用条件时分别写清。确实缺少用户才能决定的信息时，只询问该决定，继续无关工作并记录未决点。
- 不把临时指令自动提升为长期偏好，不通过改写规则绕过用户明确限制、真实设备检查或未完成验证。
- 临时防护应有复核入口；新证据支持简化或撤销时主动处理，并保留必要依据。避免规则只增不减。

## 修改闭环

- 读相关条款和当前修改状态，做最小有效更新；同步清理冲突和受影响路由。
- 回读改动，检查事实、相对链接、适用范围、重复要求和工具假设。检查通过即可，不为知识维护启动 Fusion、切片器或搭建测试服务。
- 按 [版本管理](git-workflow.md) 保存；规则修改在完整边界提交，模型记录保持本地。用户未配置远端时不创建远端。
- 在本次交付中简短说明有意义的沉淀和行为变化，无需逐条汇报常规整理，也不等待再次批准。
