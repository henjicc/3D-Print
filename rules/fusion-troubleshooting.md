# Fusion 已知故障与临时防护

> 触发：Fusion 2705.1.15 的直接 HTTP MCP 建模、空响应或资源异常；普通规则讨论不读取。本文件保留 2026-09-10 的现场证据，未声明后续版本仍有同一缺陷。

## 适用与退出条件

- 2705.1.15 直接 HTTP 写入沿用下述阶段检查及 800 / 256 防护，不因整理文档解除已有保护；收纳架客户端的写前拦截保持有效。
- 新版本或客户端变更后，根据实际实现、厂家修复信息及针对性验证重新判断适用性；有证据证明边界已改变时主动更新或撤下对应临时措施，记录依据。版本变化本身不证明故障修复。
- 资源检查无法可靠读取时暂停该路径写入，继续只读诊断和可靠的原生界面保存；不阻塞无关设计分析、规则工作或已有文件检查。
- 模型专用客户端仅在接手对应模型且文件存在时读取；其他模型按实际接口实现同样适用的防护，不无条件依赖该脚本。

### 本机已遇到的空响应故障

- 2026-09-10，Fusion 2705.1.15 端口仍监听，但 HTTP 请求立即收到空响应。进程约 7400 个文件描述符，其中约 6900 个 TCP 连接处于 `CLOSE_WAIT`，0–1023 号描述符全部占用。本机 `NsMCP10.dylib` 的 cpp-httplib `SocketStream::is_readable` 会拒绝大于 1023 的描述符；与底层库记录的 [macOS 直接关闭连接现象](https://github.com/yhirose/cpp-httplib/issues/754) 一致。随后通过 DNS 与代理连接列表的源端口交叉核对，确认目标为 `pubsub.pubnub.com:443`；这是 Fusion 云推送服务，网络失败重试是待验证触发条件，不能仅因使用代理就认定代理是根因。参考 [相似故障及 Autodesk 回复](https://forums.autodesk.com/t5/fusion-support-forum/issue-bug-macos-fusion-2704-1-53-repeatedly-crashes/td-p/14254071)。
- 同类症状先只读核对进程描述符和 TCP 状态，避免反复切换 MCP。切换时可能回退到动态端口，应看实际 URL，不能只看端口输入框。此次切换开关未恢复；用户明确允许放弃临时文档后，正常退出并重新启动 Fusion，27182 端口及实际读写恢复。
- 重启前保护未保存工作，或取得针对这些文档的明确放弃授权；此次授权不推广到未来其他设计。重启后重新握手并验证实际读写，不复用旧会话。不要外部强行关闭进程中的连接、修改厂商二进制或仅提高描述符上限。

## 临时资源防护

- 收纳架这类单机原生建模阶段，在云端交互异常且任务可本地完成时，可评估 Fusion 自带的“脱机工作”：开始前确认所需设计已本地可用、没有待完成上传或协作编辑，记录原有模式；需要云端文件、同步或云功能时联机，结束后恢复原模式并核对同步。2026-09-10 本机实测脱机时本地 MCP 握手、参数写入、F3D 导出及重新导入回读均成功。脱机测试未见原有 11 条 `CLOSE_WAIT` 增长，但联机基线当时也稳定，**未证明脱机能消除泄漏**；它是减少云端交互的可逆措施，不是永久离线方案。官方要求至少每两周联机验证；见 [脱机工作说明](https://help.autodesk.com/view/fusion360/ENU/?contextId=ASM-FUSION-OFFLINE-MODE)。
- 当前收纳架的直接 HTTP MCP 调用使用 [带保护的调用脚本](../models/sink-organizer/fusion_mcp.py)，替代临时目录中带固定会话的旧客户端。它在每次写入前检查进程资源，使用短 HTTP 连接，在一个完整操作批次结束后释放自己的 MCP 会话；同批相关操作可放在同一个 `FusionSession` 上下文中。它不运行后台服务、不自动重启、不自动重试失败写入。
- 每个完整建模阶段开始前及结束后，用只读系统查询检查 Fusion 进程的文件描述符数量、最高编号和 `CLOSE_WAIT` 数量，并与本次启动后的基线比较。不逐个特征轮询，不创建定时任务或常驻监控。
- 若最高描述符编号达到 **800**，或 0–1023 范围可用编号不足 **256**，调用脚本拒绝发送新的写入；无法可靠读取资源状态时也不发送写入。此时可继续只读诊断，通过 Fusion 原生界面保存 / 导出未保存工作，再按现场保护规则恢复。800 / 256 是为已知 1024 边界预留余量的**项目临时预警值**，不是厂家阈值或保证；已模拟验证拦截时没有发送工具请求。检查不能防止单次长操作内部突然增长，仍须分阶段操作。若占用快速增长或已发生空响应，应提前进入恢复流程；存在进行中的用户操作时不得擅自中断。
- 正常结束 MCP 会话只能清理该会话，不能保证释放 Fusion 其他模块的连接。本机实测结束会话前后仍有 11 条外部 HTTPS `CLOSE_WAIT`，当时没有 MCP 客户端残留 TCP 连接；不得把会话收尾写成根治方案。若再次快速累积，保留数量、时间及目标域名等必要诊断信息，继续查来源，不记录账号令牌或完整敏感日志。


## 单项查询与预览故障

- 2705.1.15 的 `activeCommand` 查询曾出现 UTF-8 序列化错误；可用只读脚本读取 `app.userInterface.activeCommand` 并结合 UI 核对，不将单项错误视为服务断开。

- 本机收纳架任务中，批量脚本在归档与网格导出后执行相机 / 图片导出序列曾卡住，原因未定。几何导出与预览分开；优先用已发现并实测成功的 `fusion_mcp_read`，`queryType="screenshot"` 及工具支持的标准视角生成预览，避免在同一长脚本里串接相机设置、刷新和 `saveAsImageFile`。失败先检查文件是否已导出，不重复整轮建模。
