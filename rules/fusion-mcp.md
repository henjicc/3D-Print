# Fusion 360 与 MCP 操作

> 触发：发现连接、读取 / 修改设计、参数与特征操作、导入导出、失败恢复。

## 先核实能力

1. 优先发现当前会话的 Fusion MCP 工具。若工具列表未列出 Fusion，仍通过 [项目上下文](project-context.md) 中已确认的本地 HTTP 地址直接检查 MCP；工具未注册不等于服务不可用，不必先安装另一桥接器或修改全局客户端配置。
2. 连接检查使用真实 MCP 协议：`initialize` 握手、发送 `notifications/initialized`、读取 `tools/list`，再按返回的工具定义执行只读查询。保留服务端返回的会话标识和协商版本用于后续请求，不将临时会话标识写入规则。普通网页 GET、端口监听或单次 HTTP 200 不能替代 MCP 验证。
3. 当前已验证的最小查询为 `fusion_mcp_read`，参数 `{"queryType":"document","operation":"open"}`，用于列出已打开文档；`{"queryType":"activeCommand"}` 用于读取当前命令。每次连接仍重新发现工具，不能假定后续版本契约不变。
4. 按接口实际能力只读检查应用版本、活动文档、设计模式、单位、组件 / 实体、参数和保存状态。服务端适配器版本不等于 Fusion 应用版本。
5. 握手、工具发现、只读调用和建模写入分别记录验证状态。首次建模写入在任务新文档或可恢复副本上验证，不为了测试连接修改已有模型。

## 连接失败时主动恢复

用户已授权以下恢复流程，无需为相同步骤重复请求许可：

1. 先确认 Fusion 是否运行。未打开时主动启动本机 Autodesk Fusion 应用；已确认的 macOS 路径见项目上下文。保持 Fusion 运行，等待启动完成后以有限次数重试 MCP 握手和只读查询。
2. Fusion 已运行仍无法连接时，使用 computer use 查看实际界面，进入 **Fusion → 首选项 → 常规 → API**，检查 **Fusion MCP Server**。未勾选则勾选，并按界面应用 / 保存；已勾选则不无故反复切换。
3. 核对该页面显示的端口与客户端 URL。默认端口见上下文；若用户已改端口，连接实际端口并更新项目记录，不擅自重置设置。仅连本机回环地址，不扩大到局域网或公网。
4. 设置后重新握手、发现工具并执行只读查询，成功后继续原任务。不得仅以“应用已打开”或“已勾选”宣称连接恢复。
5. 仍失败时保留现场，区分启动未完成、设置项缺失、端口不匹配、会话失效或客户端问题；会话失效时重新初始化。报告实际错误与下一步，不无限重试或把所有错误归因为软件未打开。

此授权包括启动 Fusion 和检查 / 启用上述本地 MCP 设置，不包括强退 / 重启有未保存工作的 Fusion、清缓存、安装替代服务、升级软件或修改无关系统设置。遇到登录、权限或版本问题且现有能力无法解决时再告知用户；不要把脚本生成说成已在 Fusion 执行。

### 本机已遇到的空响应故障

- 2026-09-10，Fusion 2705.1.15 端口仍监听，但 HTTP 请求立即收到空响应。进程约 7400 个文件描述符，其中约 6900 个 TCP 连接处于 `CLOSE_WAIT`，0–1023 号描述符全部占用。本机 `NsMCP10.dylib` 的 cpp-httplib `SocketStream::is_readable` 会拒绝大于 1023 的描述符；与底层库记录的 [macOS 直接关闭连接现象](https://github.com/yhirose/cpp-httplib/issues/754) 一致。随后通过 DNS 与代理连接列表的源端口交叉核对，确认目标为 `pubsub.pubnub.com:443`；这是 Fusion 云推送服务，网络失败重试是待验证触发条件，不能仅因使用代理就认定代理是根因。参考 [相似故障及 Autodesk 回复](https://forums.autodesk.com/t5/fusion-support-forum/issue-bug-macos-fusion-2704-1-53-repeatedly-crashes/td-p/14254071)。
- 同类症状先只读核对进程描述符和 TCP 状态，避免反复切换 MCP。切换时可能回退到动态端口，应看实际 URL，不能只看端口输入框。此次切换开关未恢复；用户明确允许放弃临时文档后，正常退出并重新启动 Fusion，27182 端口及实际读写恢复。
- 重启前保护未保存工作，或取得针对这些文档的明确放弃授权；此次授权不推广到未来其他设计。重启后重新握手并验证实际读写，不复用旧会话。不要外部强行关闭进程中的连接、修改厂商二进制或仅提高描述符上限。

### 当前项目的主动防护与会话收尾

- 收纳架这类单机原生建模阶段，优先评估 Fusion 自带的“脱机工作”：开始前确认所需设计已本地可用、没有待完成上传或协作编辑，记录原有模式；需要云端文件、同步或云功能时联机，结束后恢复原模式并核对同步。2026-09-10 本机实测脱机时本地 MCP 握手、参数写入、F3D 导出及重新导入回读均成功。脱机测试未见原有 11 条 `CLOSE_WAIT` 增长，但联机基线当时也稳定，**未证明脱机能消除泄漏**；它是减少云端交互的可逆措施，不是永久离线方案。官方要求至少每两周联机验证；见 [脱机工作说明](https://help.autodesk.com/view/fusion360/ENU/?contextId=ASM-FUSION-OFFLINE-MODE)。
- 当前收纳架的直接 HTTP MCP 调用使用 [带保护的调用脚本](../models/sink-organizer/fusion_mcp.py)，替代临时目录中带固定会话的旧客户端。它在每次写入前检查进程资源，使用短 HTTP 连接，在一个完整操作批次结束后释放自己的 MCP 会话；同批相关操作可放在同一个 `FusionSession` 上下文中。它不运行后台服务、不自动重启、不自动重试失败写入。
- 每个完整组件 / 建模阶段完成后，核对结果并保存独立修订的本地 F3D 检查点；文件必须非空，关键阶段回开核对。云端保存与本地归档分别确认。检查点用于在失败时恢复进度，不等待预警才第一次保存。
- 完成一个模型，或本轮 Fusion 工作结束且暂无后续调用时，等待已发出的操作完成并回读结果，确认模型已按任务要求保存，然后结束**本任务自己的 MCP 会话**并关闭客户端 HTTP / SSE 连接。不在每个草图、特征或参数调用后反复初始化；不关闭其他客户端的会话，不通过切换 MCP 开关代替正常收尾。
- 本机已验证正常结束方式：向实际 MCP URL 发送 HTTP `DELETE`，携带本任务当前的 `Mcp-Session-Id`，2026-09-10 返回 `200`。这是 [协商版本的标准会话结束机制](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports#session-management)。后续版本若返回 `405`，只关闭本客户端连接，不循环重试；下一轮重新初始化并发现工具，不复用已结束的会话。
- 每个完整建模阶段开始前及结束后，用只读系统查询检查 Fusion 进程的文件描述符数量、最高编号和 `CLOSE_WAIT` 数量，并与本次启动后的基线比较。不逐个特征轮询，不创建定时任务或常驻监控。
- 若最高描述符编号达到 **800**，或 0–1023 范围可用编号不足 **256**，调用脚本拒绝发送新的写入；无法可靠读取资源状态时也不发送写入。此时可继续只读诊断，通过 Fusion 原生界面保存 / 导出未保存工作，再按现场保护规则恢复。800 / 256 是为已知 1024 边界预留余量的**项目临时预警值**，不是厂家阈值或保证；已模拟验证拦截时没有发送工具请求。检查不能防止单次长操作内部突然增长，仍须分阶段操作。若占用快速增长或已发生空响应，应提前进入恢复流程；存在进行中的用户操作时不得擅自中断。
- 正常结束 MCP 会话只能清理该会话，不能保证释放 Fusion 其他模块的连接。本机实测结束会话前后仍有 11 条外部 HTTPS `CLOSE_WAIT`，当时没有 MCP 客户端残留 TCP 连接；不得把会话收尾写成根治方案。若再次快速累积，保留数量、时间及目标域名等必要诊断信息，继续查来源，不记录账号令牌或完整敏感日志。

## 文档与参数

- 新模型使用明确命名的设计；编辑既有模型先确认准确文档与目标组件。切换后重新确认，不能只凭窗口标题或上次对象序号。
- 默认保留参数化历史，以用户参数表达会修改的尺寸、壁厚、配合与孔位关系。草图用几何约束与尺寸表达意图；关键草图检查约束状态，不能用批量固定掩盖欠约束。
- 原点、基准面、草图平面与组件坐标保持明确。装配坐标与打印姿态可以不同，导出时核对组件实例变换，不能为落床破坏装配关系。
- 面 / 边选择先核验对象类型、方向、位置与所属实体；拓扑修改后重新查找。不能默认某索引永远代表顶面或目标孔。
- 装配中执行切削时显式指定参与实体（如 `ExtrudeFeatureInput.participantBodies`），不能以特征集合所属组件推断作用范围。写后同时核对目标与相邻实体，尤其是后建槽孔附近的格栅、定位柱；导出前要求实体有效、面数与体积均大于零，并检查小特征，不能只判断 `isSolid`。
- 用户沟通使用 mm / 度。Fusion Design 原生 API 的内部长度是 cm、角度是 rad；MCP 封装可能已转换。以当前工具契约决定转换边界，避免重复换算，写入后读回关键尺寸。
- 名称和参数表达式清楚可追踪，同一尺寸关系只有一个权威定义；不将关键数值散落在多个特征里。

## 小步执行与恢复

- 按基础形状、开孔 / 腔体、结构细节等可验证切片执行。圆角、抽壳、布尔和装配变更后检查特征状态及真实几何，不固定套用某一种特征顺序。
- 每批修改核对目标参数、实体数量、关键尺寸与意外变化；复杂内腔使用截面或测量，不只看着色视图。
- 长操作报错或超时先读回现场，判断是否已经创建部分特征。没有幂等保障时不盲重试，防止重复实体和破坏用户编辑。
- 失败保留有用错误、目标和阶段摘要，定位草图、选面、尺寸或几何根因；不静默跳过特征或缩小圆角后宣称需求完成。
- 需要回退时只撤销本次可识别的操作或恢复本次副本；不能清空设计、清缓存或关闭未保存文档来“重试”。
- 不另建日志基础设施；工具结果与必要的模型记录应能说明修改对象、结果和恢复位置，不记录凭据。

## 保存与导出

- 本机收纳架任务中，批量脚本在归档与网格导出后执行相机 / 图片导出序列曾卡住，原因未定。几何导出与预览分开；优先用已发现并实测成功的 `fusion_mcp_read`，`queryType="screenshot"` 及工具支持的标准视角生成预览，避免在同一长脚本里串接相机设置、刷新和 `saveAsImageFile`。失败先检查文件是否已导出，不重复整轮建模。

- 保存 Fusion 原生文档并核对保存结果与版本位置。原生文档是参数化设计的权威来源，STEP / 网格为交换或打印派生件。
- 按当前版本真实能力导出 3MF 或 STL。STL 没有单位元数据，明确按 mm 导出并在导入后核对尺寸；3MF 也要核对单位、对象及变换。
- 网格细化精度根据曲面、最小特征与允许几何误差选择；不能把渲染平滑当成网格精度，也不盲目用最高精度制造巨大文件。
- 核对导出对象集合、零件数量、包络、孔与局部细节、文件非空及可重新打开。保存成功与导出成功分别确认。
- 纯几何 3MF 不自动包含 Bambu Studio 的 X2D 预设、耗材映射或切片结果。只有实际保存并检查了切片项目，才称为切片项目 3MF。
- 任何源设计修改都会使相关导出件与切片失效；重新生成并按 [验证规则](testing.md) 检查后交付。
