# 文件与版本管理

> 触发：修改规则、保存模型 / 导出件、迭代或同步。

## 所有工作区

- 开始先检查已有文件及修改范围，不覆盖用户内容。只改当前任务需要的规则或模型。
- Fusion 原生版本与本地导出文件分别保存和核对；文件名、修订及参数应能对应，不能以复制同名旧文件冒充新结果。
- 重大几何修改或覆盖前保留可恢复版本；不要默认覆盖唯一原件。避免无意义副本堆积，但不在未授权时清理用户设计。
- CAD 二进制文件不能按代码逐行合并；冲突保留双方版本，在 Fusion 中核对后处理。不要自动引入 Git LFS 或新的存储服务。

## 仅对已经存在的 Git 仓库

1. 先检查仓库根目录、状态、分支及当前上游；干净且安全时 `git pull --rebase`。
2. 有其他任务未提交改动时只 fetch 检查远端，不 stash、覆盖或误提交；需要隔离时使用独立工作区。
3. 本任务完整且匹配验证通过后，按明确路径暂存，检查 staged diff，主动创建提交；禁用 `git add .`、`git commit -a` 和跳过检查钩子。
4. 提交信息使用 `<type>(可选范围): 中文说明`，规则调整使用 docs；不改写用户历史。
5. 提交后再次安全 rebase，普通推送到已配置的当前上游，检查 ahead / behind 均为 0。无上游时报告未同步，不擅自创建或选择远端。
6. 不强推、不重写共享历史。私有 CAD 或设备信息是否可进入已配置远端仍须符合已有共享范围。

目录尚未使用 Git 时，仅在用户明确要求后初始化并创建首次提交；否则跳过提交并说明。初始化前检查文件范围，忽略缓存、临时日志和中间恢复文件，正式原生模型与交付产物纳入版本管理。创建远端和发布须有对应授权，不因本地初始化自动上传。最终核对本次文件范围及意外产物；共用工作区只解释本任务剩余修改。
